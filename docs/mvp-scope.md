# MVP Scope — Circular DfMA Platform

Status: draft for discussion. Defines the bare minimum content of a lightweight MVP implementation of the core system model (library / knowledge base / priority layer / engine).

Revision 3 — element type extended with embodied GHG and cost, both staged rather than scalar and both normalised through the geometry layer. Service life now drives replacement counts over a declared study period, which turns the service-life differential from a qualitative finding into quantities in kgCO₂e and currency.

Revision 2 — element type extended with a geometric and interface layer. Geometry is carried as an envelope plus positioned interfaces in a local frame, not as a 3D model. Interfaces are the unit of geometric reasoning: fit, substitution, access and recovery are all tested against interface sets.

---

## 1. Scope boundary

One assembly, not a building.

| Dimension | MVP setting |
|---|---|
| Subject | A single external wall build-up |
| Size | 5–20 element instances |
| Layers | Two (skin over structure) |
| Lifecycle stage | Design |
| Options | Two compared variants, at least one generated by substitution lookup |
| Users | One stakeholder profile |
| Geometry | Envelope + interfaces, level G2 (see §2.6) |
| Impact scope | A1–A3, C, D reported separately; B4 derived, not entered (see §2.8) |
| Study period | Declared per project, default 60 years |

Rationale: widening scope multiplies data entry without exercising additional logic. The MVP must run the full decision-support loop once — facts → judgements → findings → ranking → decision — rather than run part of it well.

**The platform is not an LCA tool and not a cost estimator.** It consumes figures produced elsewhere, carries their provenance, and reasons about how circular DfMA decisions change them over time. It ships no factor database and calculates no emission factors of its own. Stating this boundary is what keeps the data model small and the claims defensible.

## 2. Library (facts)

Holds what things are. No judgements.

### 2.1 Element type

**Identity and lifecycle**

| Field | Type | Notes |
|---|---|---|
| `id`, `name` | string | |
| `layer` | enum | skin, structure, services, space plan, site |
| `tier` | enum | material, component, product/assembly, element |
| `service_life` | integer (years) | drives replacement count over the study period |
| `service_life_basis` | enum | warranty, standard, observed, assumed |
| `composition[]` | material + mass fraction | |
| `decomposable` | boolean | |
| `declared_recovery_pathway` | enum | reuse_as_is, remanufacture, recycle, none |
| `recovery_preconditions[]` | enum list | e.g. edges_undamaged, fixings_removable |
| `provenance` | enum | archetype, product entry |

**Geometry**

| Field | Type | Notes |
|---|---|---|
| `frame` | origin + datum face + axis convention | all interface positions are expressed in it |
| `shape_class` | enum | planar, linear, point-like, volumetric, irregular |
| `envelope` | length × width × thickness (mm) | oriented bounding box |
| `envelope_fill_ratio` | 0–1 | solid fraction of the box; corrects L-shapes, perforations, curvature without modelling them |
| `mass` | kg | density derived |
| `coordination_module` | mm, nullable | if declared, interface positions may be given as module counts |
| `orientation_constraint` | enum | none, keep_flat, keep_vertical |
| `stackable`, `nestable` | boolean | storage and transport |
| `geometry_provenance` | enum | archetype, product entry, measured |
| `interfaces[]` | list of interface records | see §2.2 |
| `g_level` | enum G0–G4 | declared completeness of geometric data |

**Embodied GHG** — one record per module, never a single number

| Field | Type | Notes |
|---|---|---|
| `declared_unit` | enum | per element, per m², per m, per kg |
| `ghg_A1A3` | kgCO₂e / declared unit | product stage |
| `ghg_A4` | kgCO₂e / declared unit, nullable | transport to site; may be derived from mass, envelope and a declared distance |
| `ghg_A5` | kgCO₂e / declared unit, nullable | installation, including waste of the connection medium |
| `ghg_C` | kgCO₂e / declared unit | end of life: deconstruction, transport, processing, disposal |
| `ghg_D` | kgCO₂e / declared unit | benefits beyond the system boundary — **stored and reported separately, never netted into any other figure** |
| `biogenic_carbon` | kgCO₂e / declared unit, nullable | held apart from fossil; not aggregated in the MVP |
| `ghg_data` | data quality record | see §2.7 |

**Cost** — three figures, because the circular argument lives in the second and third

| Field | Type | Notes |
|---|---|---|
| `currency`, `price_date` | ISO code, date | |
| `cost_supply` | per declared unit | material or product, delivered |
| `cost_install` | per declared unit | labour and plant; excludes the connection, which carries its own |
| `cost_removal` | per declared unit | labour to take out — **careful removal costs more than demolition, and that premium is the price of reversibility** |
| `residual_value` | per declared unit, may be negative | value at recovery; negative where disposal is a cost |
| `cost_data` | data quality record | see §2.7 |

`cost_removal` and `residual_value` are the fields the industry does not routinely hold. They will often be gaps. That is informative rather than fatal: the gap report naming them is itself a research finding about the data infrastructure circular DfMA would require.

**Not stored on the element type**: replacement counts, lifecycle totals, present values, payback periods. All are derived (§3.2, §5.4). Storing them would let entered facts and computed results disagree.

### 2.2 Interface record

The core geometric object. Held by the element type; realised by a connection instance in the graph.

| Field | Type | Notes |
|---|---|---|
| `id` | string | unique within the element type |
| `role` | enum | structural_bearing, weather_seal, service_connection, fixing, handling |
| `geometry_type` | enum | point, line, face, edge, socket |
| `continuous` | boolean | true for adhesive and mortar beds, seals — a field, not a discrete fixing |
| `placement` | datum face + position within it | see §2.3 |
| `orientation` | canonical direction or vector | outward normal |
| `extent` | mm / mm² | bearing length, hole diameter, seal width, contact area |
| `pattern` | count, spacing, edge offset | null for single or continuous interfaces |
| `tolerance` | ± mm | required, not optional |
| `access_direction[]` | canonical directions | from which the interface can be reached and released |
| `clearance` | direction + distance (mm) | space needed to withdraw the element |
| `admits[]` | connection type ids | which connection types this interface accepts |
| `requires[]` | conditions on the counterpart | substrate, minimum bearing depth, flatness |
| `interface_archetype_ref` | id, nullable | see below |

**Interface archetypes.** Standard interfaces (e.g. `bolt_pattern_M12_600cc`, `continuous_adhesive_bed`) are held once in the library and referenced by element types. This caps data entry, and it creates the shared vocabulary that makes signatures comparable across element types. Without it, every author invents their own interface and nothing ever matches.

**Interface signature.** Derived, not entered: a normalised string over `role + geometry_type + extent + pattern + tolerance + admits[]`. Used for matching, for inverse lookup, and for `IND-03`.

### 2.3 Position convention

Three permitted notations, in order of preference:

1. **Face-relative** — datum face + position within it ("rear face, centred, 4 fixings at 600 mm centres, 100 mm edge offset"). Default. Covers most building components at low data cost.
2. **Modular** — positions as multiples of a declared `coordination_module`. Compatibility becomes integer comparison rather than tolerance-band matching. Preferred wherever a module is declared.
3. **Absolute** — mm coordinates in the local frame. Escape hatch for non-coordinated and existing work.

The datum convention is fixed once, before any content is authored. Inconsistent origins make every comparison fail silently, which is worse than failing loudly.

### 2.4 Connection type

- `id`, `name`
- `removal_method`
- `damage_to_self` — none / minor / major
- `damage_to_host` — none / minor / major
- `re_installable` — boolean
- `access_requirement`
- `mates[]` — interface roles and geometry types it can join
- `tolerance_absorbed` — ± mm the connection can take up (shims, slotted holes, packers)
- `ghg_A1A3`, `ghg_A5` — per connection or per metre, for the fixing medium itself
- `cost_install`, `cost_removal` — per connection or per metre
- `reuse_cycles` — how many times the connection itself can be made and unmade

`tolerance_absorbed` is what makes *adapted substitution* computable. The impact and cost fields matter because **the cost of reversibility is carried by the connection, not the element** — a bracket system is more expensive and more carbon-intensive at A1–A3 than an adhesive bead, and that penalty must be visible in the same units as the benefit it buys.

### 2.5 Graph

- Element instances, each typed by an element type, each with a **placement transform** into the project frame
- **Composition edges** — part-of
- **Connection instances** — bind interface A of instance 1 to interface B of instance 2, typed by a connection type
- **Dependency edges** — removal of A requires prior removal of B

**Canonical representation rule.** Interfaces belong to element types and are potential; connections belong to the graph and are realised. Compatibility is a property of interfaces; reversibility is a property of the connection. Without this rule the two representations drift and the same joint is described twice, inconsistently.

Dependency edges are **derived** where `access_direction` and `clearance` are present (G3) — an element obstructs another if its envelope lies in the withdrawal path. Elsewhere they are asserted manually. The MVP must support both, and label which is which.

### 2.6 Levels of geometric definition

Data burden scales with the question being asked.

| Level | Adds | Enables |
|---|---|---|
| G0 | envelope, mass, orientation constraint, stackability | transport, storage, handling class, normalisation of per-m² and per-kg figures |
| G1 | shape class, interfaces with roles assigned to faces | access, coarse fit |
| G2 | positioned interfaces with patterns and tolerances | substitution test, interface diversity |
| G3 | clearance vectors, handling points | derived dependency, disassembly sequencing |
| G4 | link to external geometry file, referenced not parsed | deferred |

**MVP requires G2 for all element types in the wall, and G3 for one element.** G0 is now a precondition for any impact or cost result, since it supplies the quantity that per-m² and per-kg figures are multiplied by.

### 2.7 Data quality record

Attached to every GHG and cost figure. No bare numbers enter the library.

| Field | Type | Notes |
|---|---|---|
| `source` | citation | EPD number, database release, tender return, published rate |
| `data_type` | enum | product-specific EPD, industry average, generic database, estimate |
| `vintage` | year | figures age; a 2016 grid-based factor is not a 2026 one |
| `geography` | region code | |
| `uncertainty` | ± % or range | required; estimates take a wide band rather than no band |
| `basis_note` | free text | what is included and excluded |

**Uncertainty is not decoration.** The engine must report two options whose difference falls inside the combined band as *indistinguishable on that dimension* rather than ranking them. Without this, the platform manufactures false precision and a 3% carbon difference between two generic figures becomes a design decision it cannot support.

### 2.8 Project parameters (assessment conventions)

Facts about the assessment, not preferences. Declared once per project, and reported on every output.

| Parameter | Default | Notes |
|---|---|---|
| `study_period` | 60 years | reference period against which replacements are counted |
| `discount_rate` | 0%, plus a declared sensitivity rate | see below |
| `currency`, `price_date` | project-declared | all figures normalised to it |
| `transport_distance` | nullable | only if A4 is derived rather than entered |
| `grid_assumption` | static | future decarbonisation is **not** modelled in the MVP; stated as an assumption |

**Discounting.** A replacement in year 50 is not worth its nominal cost today, and the choice of rate decides many circular arguments on its own. The MVP reports lifecycle cost undiscounted *and* at one declared rate, and runs the existing rank-stability check across rates. Hiding the rate inside a single number would be the least defensible thing the platform could do.

### 2.9 Excluded from MVP

Event timeline; solid or parametric 3D modelling; IFC/Revit import; curved and non-orthogonal geometry; bundled LCA or cost databases; full EN 15978 B-module modelling beyond B4 replacement; dynamic grid factors; material passport integration.

## 3. Knowledge base (judgements)

Holds what follows from the facts. Every entry is scoped, bound to required library fields, cited, and declares the rules it opposes.

### 3.1 Rule schema

- `id`
- `kind`: derivation | criterion | indicator
- `scope`: tier, layer, stage
- `requires[]`: library fields the rule depends on — **including geometric fields, G-level, and named impact or cost modules**
- `logic`
- `output`: finding text, severity, recommended action
- `source`: citation
- `opposes[]`: rule ids

A rule that requires G2 geometry or a `ghg_C` figure must declare it. Running it against data that lacks either produces a gap entry, not a result.

### 3.2 Minimum rule content

**Derivations (7)**

- `DRV-01` Reversibility, from removal method + damage expectation.
- `DRV-02` Highest recoverable tier, from decomposability + contamination.
- `DRV-03` **Substitutability grade** — direct / adapted / incompatible, from interface congruence, tolerance and `tolerance_absorbed` (§5.2).
- `DRV-04` **Handling class** — one-person / two-person / mechanical, from mass + maximum envelope dimension.
- `DRV-05` **Replacement count** — `ceil(study_period ÷ service_life) − 1`. Turns service life into a quantity.
- `DRV-06` **Cascading replacement** — where `damage_to_host` is major, replacing the shorter-life element forces replacement or repair of the host, so the host's effective replacement count follows the shorter element's cycle. This is the single most consequential derivation in the model: it converts the service-life differential from an argument into kgCO₂e and currency.
- `DRV-07` **Lifecycle GHG and cost over the study period** — A1–A3 + A4 + A5, plus replacement cycles from `DRV-05`/`DRV-06` including their connections, plus C. Module D reported alongside, never inside.

**Criteria (6)**

- `CON-001` Irreversible joint across a service-life differential above threshold.
- `CON-002` **Access obstruction** — the withdrawal clearance of a shorter-life element is occupied by a longer-life element.
- `CON-003` **Recovery not worth doing** — `cost_removal` exceeds `residual_value` by more than a declared margin, or `ghg_C` of careful deconstruction exceeds the `ghg_D` credit it enables. A declared recovery pathway that fails this test is aspirational, and the platform should say so.
- `REC-001` Declared recovery pathway contradicted by the installed connection.
- `SEP-001` Material separability at end of life.
- `DFM-001` A DfMA criterion opposing a circularity criterion (part-count reduction through bonding). Now quantified on both sides: it carries the A1–A3 and capital saving, against `DRV-07`'s replacement burden.

`DFM-001` is not optional. Without an opposing rule the engine never produces a trade-off, and trade-off handling is the concept's distinguishing claim. With GHG and cost present, the trade-off stops being two opinions and becomes two numbers with a crossover point.

**Indicators (8)**

- `IND-01` Mass fraction recoverable at component tier.
- `IND-02` Fraction of connections reversible.
- `IND-03` Interface diversity — distinct signatures ÷ total interfaces.
- `IND-04` Transport density — recoverable mass ÷ envelope volume.
- `IND-05` **Upfront embodied GHG** — A1–A5, per m² of assembly.
- `IND-06` **Lifecycle embodied GHG over the study period** — including replacement cycles and C. Reported with the D credit stated separately.
- `IND-07` **Lifecycle cost over the study period** — capital, replacement, removal, less residual value. Undiscounted and at the declared rate.
- `IND-08` **Break-even of reversibility** — the year, or number of reuse cycles, at which a reversible option's higher upfront GHG or cost is repaid by avoided replacement. Reported as two numbers (carbon break-even, cost break-even) which frequently disagree, and that disagreement is the finding.

`IND-08` is the indicator with the strongest claim to research value. It is also the most assumption-laden, so it must be reported with the study period, discount rate, static-grid assumption and uncertainty bands attached, and suppressed entirely when the inputs are estimates with wide bands.

### 3.3 Non-negotiable

Every finding carries its rule id, the input values that triggered it, and its source. Geometry-derived findings carry `geometry_provenance` and G-level. Impact and cost findings carry `data_type`, `vintage` and `uncertainty`, and the project parameters in force. Module D is never netted. No aggregation into a single score.

## 4. Priority layer (preferences)

- **Constraints** — exclude options outright (e.g. capital cost cap, upfront carbon cap).
- **Targets** — declared against a named indicator, with a threshold.
- **Profile** — one stakeholder, an ordered sequence of ≤4 dimensions, plus an indifference band.

Operations, in order:

1. Constraint filter
2. Dominance elimination
3. Lexicographic ranking under the profile
4. Rank-stability check — across dimension reordering **and across the declared discount rates**

The indifference band in the profile and the uncertainty band on the data are different things and must stay separate. The first is a preference ("I do not care about cost differences under 5%"); the second is a fact about the evidence ("these two figures cannot be distinguished"). Collapsing them would let a stated preference launder a data weakness.

Options may be supplied by the substitution lookup rather than hand-authored. Multi-stakeholder negotiation is out of scope.

## 5. Engine

Deterministic and rule-driven. No AI, no optimisation search, no automatic redesign.

### 5.1 Evaluation cycle

1. Bind each rule to matching subjects in the graph by scope.
2. Check `requires[]` against available fields, the subject's G-level, and the presence of named impact and cost modules; a shortfall produces a gap entry, never a silent pass.
3. **Normalise** — convert every per-m², per-m and per-kg figure to per-element using the envelope and mass, then to the assembly quantity (§5.4).
4. Evaluate and emit findings, flagged provisional where values derive from an archetype, a generic factor or an estimate.
5. Detect opposing rules firing on the same subject; emit a trade-off holding both positions, the deciding conditions, and the crossover point where one now exists.
6. Compute indicators with propagated uncertainty, compare options, rank, report target compliance.
7. Emit a gap report: missing fields, insufficient G-level, missing modules, provisional values, single-source values, stale vintages.

### 5.2 Compatibility test

Runs when a slot is queried for candidates, or when two options are compared.

1. **Envelope fit** — candidate envelope within the available void, plus tolerance.
2. **Interface congruence** — for each interface the host requires: matching `role`, compatible `geometry_type`, position congruent within the larger of the two tolerances, matching `orientation`, and an admissible connection type.
3. **Adapter test** — where mismatch falls within the connection's `tolerance_absorbed`, or an adapter would close it. **An adapter is an element and carries its own GHG and cost**, which enter the comparison.
4. **Knowledge-base criteria** — performance, layer, service life. Run last.

| Outcome | Condition | Report |
|---|---|---|
| Direct substitution | all interfaces congruent as-is | matched signature set |
| Adapted substitution | mismatch absorbed by connection tolerance or a named adapter | the mismatch, the adapter required, and its added GHG and cost |
| Incompatible | at least one required interface unmatched | the failing interface and the reason |

### 5.3 Substitution lookup

- **Forward** — given a slot, return library element types that fit it, graded, with lifecycle GHG and cost deltas against the incumbent.
- **Inverse** — given an element type's signature set, return slots it could fill. Supports reuse in other projects and a future component register.

Both are filters over the declared library, not searches over a design space.

### 5.4 Quantity and normalisation rules

Written out because this is where silent errors enter.

- Declared units resolve through geometry: per m² uses the envelope's face area × `envelope_fill_ratio`; per kg uses `mass`; per m uses the governing envelope dimension.
- Assembly quantity = instance count × per-element figure. Waste and offcut allowances are **not** modelled in the MVP; the assumption is declared.
- Connection figures are counted per connection instance in the graph, from `pattern` counts where the interface is patterned and per metre where it is continuous.
- Replacement events reapply the element figure **and its connection figures**, which is exactly where a reversible joint earns its premium back.
- Uncertainty propagates as a simple interval, not a distribution. Monte Carlo is deferred; interval arithmetic is enough to establish indistinguishability, which is all the ranking needs.

## 6. Interface (application)

- **Input**: structured form or spreadsheet/JSON. Manual entry. Interface archetypes selected by reference. GHG and cost entered with their data quality record in the same form — the record is not a separate optional step.
- **Output**: per-option findings report; option comparison table showing upfront and lifecycle GHG and cost with bands; compatibility report with grades and reasons; break-even chart or statement for `IND-08`; gap report. Exportable.
- **Geometry display**: schematic elevation or section showing interface positions on faces. A diagram, not a modeller.
- **Excluded**: BIM integration, automated model ingestion, 3D viewer, factor database browsing.

---

## 7. Acceptance tests

The MVP is complete when all seven pass.

1. **Reproduction** — it reproduces the wall build-up example end to end.
2. **Propagation** — changing one library fact (adhesive bond → mechanical fixing) propagates unaided to derived reversibility, findings, indicator values and ranking order, with no edit to any rule.
3. **Substitution** — a slot query over at least six candidate element types returns each correctly graded direct / adapted / incompatible, matching a hand-checked answer key.
4. **Geometric sensitivity** — changing a fixing pattern from 600 mm to 450 mm centres moves an affected candidate from direct to adapted or incompatible, and names the interface responsible.
5. **Cascading replacement** — setting `damage_to_host` from minor to major on the skin-to-substrate joint must raise the substrate's derived replacement count, and must move both `IND-06` and `IND-07` by the corresponding quantity. The report must name `DRV-06` as the cause. This is the test that proves the circular argument is computed rather than asserted.
6. **Study-period and discount sensitivity** — changing `study_period` from 60 to 30 years, and the discount rate from 0% to 5%, must change `IND-07` and `IND-08` and must be reported as an assumption change, not a data change. A ranking that flips must be flagged by the rank-stability check rather than silently reversing.
7. **Indistinguishability** — two options whose lifecycle GHG differ by less than the combined uncertainty band must be reported as indistinguishable on that dimension and must not be ranked by it. A ranking produced on a difference smaller than its own error bar is a failure, not a result.

Tests 5 and 7 are the decisive ones. Test 5 shows that GHG and cost are wired to the disassembly logic rather than sitting beside it; test 7 shows the platform refuses to overstate what its data supports. Test 2 remains the structural test of facts / judgements / preferences separation.

## 8. Evaluation measures

How the MVP is judged once it runs, beyond passing the tests.

| Measure | Method | Threshold |
|---|---|---|
| Data burden, element type | Time a practitioner entering one planar component at G2 with GHG and cost, using archetypes | ≤ 8 minutes |
| Data burden, assembly | Time entering the full wall, 5–20 instances | ≤ 35 minutes |
| Compatibility accuracy | Grades against a hand-checked answer key over six candidates | no false "direct" |
| Arithmetic verification | Recompute `IND-05` to `IND-08` by hand for both options | exact agreement, all figures |
| Gap completeness | Remove fields deliberately — including `cost_removal` and `residual_value` — and confirm each surfaces as a gap | 100% |
| Uncertainty discipline | Inject two figures with overlapping bands; confirm no ranking is produced on that dimension | no ranked output |
| Provenance carriage | Confirm every reported figure traces to source, data type, vintage and geography | all figures |
| Explanation adequacy | A reader reconstructs why each finding fired from the report alone | all findings |

The two failure modes that would discredit the platform are a candidate wrongly reported as a drop-in replacement, and a carbon or cost ranking asserted on a difference smaller than the uncertainty in its inputs. Both are tested explicitly.

## 9. Principal risks at this scope

| Risk | Consequence | Mitigation in MVP |
|---|---|---|
| Scalar impact figures | A single kgCO₂e number cannot express the replacement argument, which is the whole case for reversibility | Modules stored separately; B4 derived from service life |
| Module D netted into totals | The most common misuse of LCA in circularity claims; inflates the case for reuse | D stored and reported separately, never summed |
| False precision | Rankings on differences smaller than the data's error | Uncertainty required on every figure; indistinguishability rule in the engine |
| Missing cost of removal and residual value | The circular case cannot be made in cost terms at all | Fields exist and their absence is reported as a gap, not filled with a guess |
| Discount rate hidden | The rate quietly decides the recommendation | Undiscounted plus one declared rate, with rank stability across rates |
| Static grid assumption | Long-horizon carbon comparisons are sensitive to future decarbonisation | Declared as an assumption on every output; dynamic factors deferred |
| Data burden, now with GHG and cost | Practitioners abandon entry | Archetype defaults; figures optional at G0 with results degrading to gaps rather than failing |
| Datum convention drift | Every geometric comparison fails silently | Convention fixed before authoring; validated on entry |
| Tolerance brittleness | Small differences defeat matching | `tolerance` required; modular notation preferred |
| Continuous interfaces misread | Adhesive beds represented as fixing patterns | `continuous` flag, distinct primitive |
| Double representation | The same joint described twice, inconsistently | Canonical representation rule, §2.5 |
| Undefined conflict semantics | Knowledge base becomes unauditable | Specify `opposes[]` and trade-off output before rule content is authored |
| Perceived value | A single wall invites an industry "so what" | Ship substitution lookup, quantified trade-off and break-even, not single-option assessment |

---

## 10. Deliberately deferred

Bundled LCA and cost databases; full EN 15978 B-module modelling; dynamic grid and future factor scenarios; Monte Carlo uncertainty; operational energy; biogenic carbon accounting; waste and offcut allowances; solid and parametric geometry; IFC/Revit ingestion; curved and non-orthogonal elements; 3D viewer; multi-stakeholder negotiation; material passport integration; a cross-project component register built on inverse lookup; automated design search; building-wide roll-up; any composite score.
