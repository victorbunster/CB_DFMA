# Core system model

The system has three content components, executed by an engine that holds no domain content of its own.

The **element type library** holds facts: element types, interfaces, connection types, assembly patterns, and the graph of a given building — elements linked by composition, connection and dependency edges, with a timeline of events.

The **knowledge base** holds judgements: derivations, criteria, rules and indicator definitions — each scoped to the tiers, layers and stages where it applies, bound to the library fields it requires, cited to a source, and declaring the rules it is known to oppose.

The **priority layer** holds preferences: constraints, targets and stakeholder profiles — constraints excluding options outright, targets declared against named indicators, and profiles ordering the surviving options by a stated sequence of dimensions, one profile per stakeholder.

The **engine** evaluates knowledge against the model and returns findings, indicator results, comparisons and gaps.
